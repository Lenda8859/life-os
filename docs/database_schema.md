# Схема базы данных

## Реализовано в первой итерации базы

### `life_areas`

Хранит редактируемые жизненные сферы пользователя.

| Столбец | Назначение |
|---|---|
| `id` | Первичный ключ |
| `name` | Уникальное название |
| `description` | Необязательное описание |
| `priority` | Приоритет от 1 до 5 |
| `current_score` | Текущая оценка от 1 до 10 |
| `desired_score` | Желаемая оценка от 1 до 10 |
| `is_archived` | Признак архивирования |
| `created_at` | Дата создания |
| `updated_at` | Дата изменения |

### `goals`

Хранит цели и связывает их с жизненной сферой.

| Столбец | Назначение |
|---|---|
| `id` | Первичный ключ |
| `life_area_id` | Внешний ключ на `life_areas.id` |
| `title` | Название цели |
| `description` | Подробное описание |
| `start_date` | Дата начала |
| `target_date` | Плановая дата завершения |
| `horizon` | Горизонт планирования |
| `priority` | Приоритет от 1 до 5 |
| `status` | Текущее состояние |
| `progress_percent` | Прогресс от 0 до 100 |
| `achievement_criteria` | Критерий достижения |
| `is_archived` | Признак архивирования |
| `created_at` | Дата создания |
| `updated_at` | Дата изменения |

## Связь

```text
life_areas 1 ─── N goals
```

Каждая цель обязательно относится к существующей жизненной сфере. Удаление
сферы с целями ограничивается внешним ключом. В пользовательском интерфейсе
важные записи будут архивироваться, а не удаляться.

Остальные таблицы будут добавляться отдельными миграциями вместе с модулями.
