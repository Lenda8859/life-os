### Почему проект разделён на файлы

Если разместить весь код в `app.py`, файл быстро станет большим и запутанным.
Поэтому у каждой части есть своя ответственность:

- `app.py` запускает приложение;
- `config.py` хранит общие настройки;
- `dashboard.py` формирует стартовую страницу;
- `styles.css` отвечает за оформление;
- `tests/` хранит проверки;
- `docs/` хранит документацию.

Такое разделение называется **разделением ответственности**.

окружение и устанавливает зависимости из файлов requirements.

## 5. Зависимости проекта

Файл `requirements.txt` содержит библиотеки, необходимые приложению:

```text
streamlit>=1.40,<2.0
```

Запись означает:

- версия Streamlit должна быть не ниже `1.40`;
- версия должна оставаться ниже `2.0`.

Файл `requirements-dev.txt` содержит инструменты разработки:

```text
-r requirements.txt
pytest>=8.0,<9.0
ruff>=0.9,<1.0
```

Строка `-r requirements.txt` говорит pip сначала прочитать основной список
зависимостей.

Установка:

```powershell
python -m pip install -r requirements-dev.txt
```

Во время первой установки возникали сетевые тайм-ауты и ошибка повреждённого
кэша. Для повторной загрузки использовался запуск без кэша:

```powershell
python -m pip install streamlit --no-cache-dir --timeout 300 --retries 10
```

Это не было ошибкой кода Life OS: сбой происходил при скачивании пакетов.

## 6. Точка входа `app.py`

Файл `app.py` — начало выполнения приложения.

```python
from life_os.pages.dashboard import render_dashboard
```

Здесь используется `import`: функция `render_dashboard` импортируется из другого
модуля.

```python
def main() -> None:
```

Объявляется функция `main`.

- `def` создаёт функцию;
- `main` — её имя;
- `()` означает, что функция не принимает аргументы;
- `-> None` — type hint, показывающий, что функция ничего не возвращает.

```python
if __name__ == "__main__":
    main()
```

Этот блок запускает `main()` только при непосредственном запуске `app.py`.
Если файл будет импортирован в тест или другой модуль, приложение автоматически
не запустится.

### Почему импорт Streamlit находится внутри `main`

Так метаданные проекта можно импортировать в простых тестах независимо от
запущенного интерфейса. Позднее мы продолжим отделять интерфейс от логики.

## 9. Страница `dashboard.py`

Стартовая страница разделена на небольшие функции:

- `load_styles()` загружает CSS;
- `render_sidebar()` показывает боковую панель;
- `render_dashboard()` собирает главную страницу.

### Работа с путём к CSS

```python
STYLES_PATH = Path(__file__).resolve().parents[1] / "assets" / "styles.css"
```

`Path` из стандартного модуля `pathlib` помогает работать с путями независимо
от текущего каталога запуска.

### Работа с датой

```python
today = date.today().strftime("%d.%m.%Y")
```

- `date.today()` получает текущую дату;
- `strftime()` преобразует её в строку;
- `%d.%m.%Y` задаёт формат `день.месяц.год`.

### Колонки Streamlit

```python
columns = st.columns(4)
```

Streamlit создаёт четыре колонки для карточек показателей.

### Цикл и распаковка

```python
for column, (title, value, caption, color) in zip(columns, cards, strict=True):
```

Здесь:

- `for` перебирает элементы;
- `zip` объединяет колонку и описание карточки;
- значения карточки распаковываются в четыре переменные;
- `strict=True` помогает заметить ошибку, если количество колонок и карточек
  не совпадёт.

## 11. Первый автоматический тест

Файл `tests/test_app.py` проверяет основные метаданные:

```python
def test_application_metadata() -> None:
    assert APP_NAME == "Life OS"
```

Правила pytest:

- имя файла начинается с `test_`;
- имя тестовой функции начинается с `test_`;
- `assert` проверяет условие;
- если условие ложно, тест завершается ошибкой.

Запуск:

```powershell
python -m pytest
```

Фактический результат первой итерации:

```text
1 passed
```

Тесты важны, потому что позволяют автоматически заметить поломку уже
работающего поведения.

## 15. Публикация на GitHub

Был создан публичный репозиторий:

```text
https://github.com/Lenda8859/life-os
```

Локальная ветка была переименована из `master` в `main`:

```powershell
git branch -M main
```

GitHub был подключён под именем `origin`:

```powershell
git remote add origin https://github.com/Lenda8859/life-os.git
```

Первый push:

```powershell
git push -u origin main
```

- `push` отправляет локальные коммиты на GitHub;
- `origin` — имя удалённого репозитория;
- `main` — имя ветки;
- `-u` связывает локальную и удалённую ветки.

Обычный пароль GitHub для Git-операций не используется. Авторизация была
выполнена через Git Credential Manager и браузер.
